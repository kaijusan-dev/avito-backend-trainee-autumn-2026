
# CJM - Со стороны клиента

## Цель

Показать, как клиент пользуется Avito.Kitchen: выбирает заведение, просматривает меню, оформляет заказ и получает информацию о его статусе.

## Участник

**Клиент** - человек, который хочет заказать еду с самовывозом или доставкой.

## Основной сценарий

### 1. Выбор заведения

Клиент запрашивает список доступных заведений.

- Platform API получает список активных заведений из своей базы данных.
- Клиент выбирает подходящее заведение.

**Результат:** клиент получил список заведений и выбрал одно из них.

### 2. Просмотр меню

Клиент открывает меню выбранного заведения.

- Platform API проверяет, что заведение существует и активно.
- Platform API запрашивает меню у Restaurant API.
- Restaurant API возвращает доступные данные о меню.

**Результат:** клиент видит меню выбранного заведения.

### 3. Формирование заказа

Клиент выбирает товары и указывает необходимую информацию:

- имя;
- номер телефона;
- способ получения заказа: самовывоз или доставка;
- адрес доставки, если выбран соответствующий способ;
- товары и их количество.

### 4. Проверка заказа

Перед созданием заказа Platform API обращается к Restaurant API.

Restaurant API возвращает информацию о запрошенных товарах:

- существуют ли товары;
- доступны ли они для заказа;
- какова их актуальная стоимость.

Platform API проверяет полученные данные и рассчитывает итоговую стоимость заказа.

**Результат:** заказ проверен, итоговая стоимость рассчитана.

### 5. Создание заказа

После успешной проверки:

1. Platform API сохраняет заказ и его позиции в своей базе данных.
2. Platform API передаёт заказ в Restaurant API.
3. Restaurant API сохраняет заказ в своей базе данных.

Оба сервиса используют одинаковый идентификатор заказа. Это позволяет связать записи без обращения к чужой базе данных.

**Результат:** заказ создан и передан заведению.

### 6. Получение информации о заказе

Клиент запрашивает информацию о заказе по его идентификатору.

- Platform API получает основную информацию о заказе из своей базы данных.
- Затем Platform API запрашивает актуальный статус у Restaurant API.
- Клиент получает информацию о заказе с актуальным статусом.

**Результат:** клиент может узнать текущее состояние заказа.

## Краткая схема сценария

1. Клиент -> Platform API: запрос списка заведений.
2. Клиент -> Platform API: запрос меню.
3. Platform API -> Restaurant API: получение меню.
4. Клиент -> Platform API: создание заказа.
5. Platform API -> Restaurant API: проверка товаров.
6. Platform API -> Platform PostgreSQL: сохранение заказа.
7. Platform API -> Restaurant API: передача заказа.
8. Restaurant API -> Restaurant PostgreSQL: сохранение заказа.
9. Клиент -> Platform API: запрос информации о заказе.
10. Platform API -> Restaurant API: получение актуального статуса.

## Возможные проблемы

- Заведение не найдено или неактивно.
- Товар не найден.
- Товар недоступен для заказа.
- Сервис заведения временно недоступен.
- Переданные клиентом данные не прошли проверку.

В таких случаях API возвращает соответствующую HTTP-ошибку.
